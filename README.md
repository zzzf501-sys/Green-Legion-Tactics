# 绿色军团 — 热座回合制策略游戏

> Green Army Men — Hotseat Turn-Based Strategy Game

基于 HTML5 Canvas 的本地热座（Hotseat）回合制策略游戏，支持 2~4 人轮流在同一台电脑上操作。

---

## 快速开始

直接双击 `game.html` 即可开始，**无需安装任何环境**（推荐 Chrome/Edge 浏览器，按 F11 全屏）。

## 游戏规则

### 目标
摧毁所有敌方大本营，或消灭所有敌方单位。

### 流程
1. 所有玩家轮流操作——**所有玩家都行动完 = 1 回合**
2. 单位每回合可：**先移动 → 后攻击**（可多次攻击，每点击算一次）
3. **新造单位当回合不能行动**，休息到下回合才可操作
4. 可行动单位：脚下有玩家颜色小圈；已行动/新造单位：无小圈
5. 归属标识：玩家颜色方框框住整格

### 玩家颜色
| 玩家 | 颜色 |
|:---:|:----:|
| P1 | 🔴 红 |
| P2 | 🔵 蓝 |
| P3 | 🟢 绿 |
| P4 | 🟡 黄 |

### 战斗公式
```
伤害 = max(0, 攻击方攻击力 − 防守方护甲)
```
- 距离计算：**欧几里得距离**（实际根号距离）
- 多次攻击：每点击算一次攻击，一回合可多次攻击
- 装甲车攻击 3 次
- 轰炸机每 2 回合攻击一次（装弹 1 回合），爆炸半径 1.5
- 高爆炮爆炸半径 2
- 自杀无人机攻击后自毁

### 地形
- 地形分为平地、丘陵、高地、山脉四级高度
- 每局会随机生成横向、纵向或斜向的细断续山势主线及其中心对称副本，3/4 人大地图会出现更多方向的蜿蜒山势；整体以平地和丘陵为主，少量高地与山峰
- 地面单位上坡移动消耗更高，下坡移动消耗更低；空中单位移动不受地形消耗影响
- 攻击方比目标更高时有效射程增加，低打高时有效射程降低，射程修正最多 ±2
- 山脉可以通行，但移动消耗最高

### 战争迷雾
- 地图地形始终可辨认，但当前视野外会被暗雾覆盖并轻微流动
- 己方单位和建筑提供视野；地面单位站在高处时视野额外增加对应高度
- 视野外敌方单位不可见、不可被选中或攻击；已探索过的敌方建筑会保留已知位置
- 视野公式：视野 = 射程 + 移速，侦察机例外固定为 11
- T3 战略科技 SpaceX 星链计划完成后，本玩家获得全图视野

### 金钱与经济
- 起始资金：**12 金币**
- 数值运算保留 2 位小数
- 大本营每回合产出金币（T1: +4.5, T2: +7.5, T3: +12）
- 据点被占领后每回合产出金币（+4.5）

### 资源采集器（T2 解锁）
- 建造费用：🪙8，建造时间：**2 回合**
- **产出递减**（按采集器编号计算）：

| 编号 | 每回合产出 |
|:---:|:---------:|
| 0 | 🪙 4.50 |
| 1 | 🪙 3.60 |
| 2 | 🪙 2.88 |
| 3 | 🪙 2.30 |

- 采集器被摧毁后编号保留，新建自动填补空缺最小序号
- 建造虚影上会显示**预计每回合产出**

### 大本营升级
| 等级 | 费用 | 时间 | HP | 护甲 | 产出 | 驻扎范围 |
|:---:|:----:|:----:|:--:|:----:|:---:|:-------:|
| T1→T2 | 🪙10 | ⏳3 回合 | 15 | 0.5 | +7.5 | 3格 |
| T2→T3 | 🪙30 | ⏳5 回合 | 50 | 1 | +12 | 5格 |

- 大本营升级恢复失去血量的 50%（按比例）

### 建筑自回血
所有建筑连续 2 回合未受攻击后，从第 3 回合起每回合自动恢复 **2 HP**，受击即中断。

### 驻扎系统
| 建筑 | 驻扎范围 |
|:----|:--------:|
| 🏰 大本营 T1/T2 | 3格 |
| 🏰 大本营 T3 | 5格 |
| 🏴 T1据点 | 2格 |
| ⚔️ 战斗型T2据点 | 3格 |
| 💰 经济型T2据点 | 2格 |

驻扎后每回合回 2 HP。

### 据点系统
- 地图上分布中立据点，初始 20 HP、0 护甲，实际出生为 50%HP
- **可反复易手**：谁打爆最后一滴血 → 据点归谁
- 占领后每回合 +4.5 金币
- T2 升级（需大本营 T2 自动解锁）：

| 分支 | HP | 护甲 | 金币/回合 | 升级时间 | 升级效果 |
|:---:|:--:|:----:|:---------:|:--------:|:--------|
| ⚔️ 战斗型 | 30 | 0.5 | 6 | 1回合 | 回满血量 |
| 💰 经济型 | 20 | 0 | 9 | 3回合 | 恢复50%失去血量 |

- T2 据点被打爆 → 退回 T1，50%HP，归属攻击方

### 装备回血
装备新装备时触发回血：`新HP = 新满血 × (1 + 旧HP/旧满血) ÷ 2`

## 远程联机

当前联机版采用 Node.js + WebSocket 的房间同步方案：服务器负责创建房间、分配玩家编号、保存最新棋盘状态并广播给其他玩家；客户端负责执行本地操作并同步状态。此版本优先保证两名玩家能远程玩起来，后续可继续升级为服务器权威判定。

### 本地启动联机服务器

```bash
npm install
npm start
```

启动后浏览器打开：

```text
http://localhost:3000
```

### 云服务器部署

1. 在云服务器安装 Node.js LTS。
2. 上传整个项目文件夹。
3. 在项目目录运行：

```powershell
npm install
npm start
```

4. 云厂商防火墙和 Windows 防火墙都放行 TCP `3000`。
5. 玩家浏览器打开：

```text
http://服务器公网IP:3000
```

### 联机流程

1. 主机点”远程联机”。
2. 服务器地址填 `ws://服务器公网IP:3000`（本地测试用 `ws://localhost:3000`）。
3. 选择人数，点击”创建房间”。
4. 系统自动生成房间号并显示在状态栏，把房间号发给朋友。
5. 朋友打开同一个网页，点”远程联机”，输入相同服务器地址，点击”加入房间”，在弹出的对话框中输入房间号。

## 文件结构

```
strategy-game/
├── game.html              ← 主游戏入口
├── README.md              ← 本文档
├── start.bat              ← Windows 快速启动脚本
├── package.json           ← 联机服务器依赖与启动脚本
├── package-lock.json      ← npm 依赖锁定
├── server/
│   └── server.js          ← Node.js HTTP + WebSocket 房间服务器
├── src/
│   ├── data.js            ← 兵种/建筑/装备数据
│   ├── main.js            ← 游戏主逻辑、回合系统、渲染与交互
│   └── online.js          ← 联机客户端、房间连接与状态同步
├── styles/
│   └── main.css           ← 主游戏样式
├── assets/
│   ├── images/            ← 图片素材（单位、建筑、UI、地形、胜利图）
│   └── audio/             ← 音频素材（BGM 与音效）
└── encyclopedia/
    └── index.html         ← 兵种/装备/建筑数据百科 + 战斗推演器
```

### 技术架构
- **渲染**：HTML5 Canvas，60fps requestAnimationFrame
- **摄像机**：平滑 lerp 缩放/平移，滚轮以光标为中心缩放
- **类结构**：`Game` → `Grid` / `Camera` / `Unit` / `Building` / `Player`
- **距离**：欧几里得距离（实际根号距离）
- **寻路**：BFS 移动范围
- **存档**：无需存档，热座模式同一台电脑轮流操作
- **资源组织**：图片与音频分离存放，主入口通过独立 CSS/JS 文件加载
- **远程联机**：Node.js HTTP 静态服务 + WebSocket 房间同步
